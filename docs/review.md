# Qualified dependency review contract

Schema version 1 emits format/identity kind, installed_path (null for resolution records), topology_status, root_attribution_status and execution_metadata_status alongside `status: complete|incomplete`, an explicit scope and byte hashes. `complete` refers only to extraction of provided records and declared markers, never verified artifact contents or runtime safety. JSON parse failures use an incomplete error envelope. Policy is separate: `advisory|allowed|blocked|incomplete` with `enforcement_requested` and unapproved coordinates. Review is advisory.

npm instances use installation-path identities; pnpm uses full namespaced snapshot contexts, and Yarn uses canonical descriptor groups. None are collapsed by package name. Nested/contextual versions remain distinct. Edges are directed and carry sorted kinds: dependencies, devDependencies, optionalDependencies, peerDependencies and workspaceLink. Multiple kinds share one topology edge. npm optionalDependencies override same-name dependencies. Nearest installed node_modules instances resolve dependency targets; workspace links connect to lockfile workspace records. Missing required targets are issues; absent optional peers/optional dependencies are reported separately as optional omissions. Platform filtering is not inferred.

Every declared install marker and supplied root lifecycle script appears in execution_candidates, including unreachable candidates (null introducer path) and one-node roots. Root preinstall/install/postinstall/prepare bodies are SHA-256 identified; dependency bodies are not read. Binary entrypoints are identified separately, since they are not automatically installation execution. Paths include typed edges and use deterministic breadth-first traversal. Marker approvals match exact name@version, without wildcard scope matching or artifact pinning. Unknown pnpm/Yarn execution metadata always prevents an allowed enforcement outcome.

Reviews return complete base/head reports and package_changes keyed by the format-specific record identity (npm installation path, pnpm snapshot context or Yarn descriptor group). Same-version source/integrity changes are meaningful. Added/removed typed edges include edge-kind changes. Formatting-only changes affect byte hashes without creating package changes. Unreachable records are included and identified; the lockfile is not asserted to reproduce a host's actual install selection.

Limits: npm lockfileVersion 3, pnpm v9 and Yarn Classic v1 supported subsets; input JSON <=64 MiB with nesting <=128; strict grammar, duplicate-key rejection and finite numbers. Custom config supports three named keys with quoted strings/string arrays, comments and multiline arrays. Unsupported or invalid data fails visibly. The std-only SHA-256 identifies consumed bytes, not the publisher or artifact authenticity. Parser inputs are untrusted; arbitrary FFI pointers cannot be made safe by validation.

Math is diagnostic: maximum-gap partition of a bounded sparse iteration, at most 5000 steps; residual convergence and iterations accompany every estimate. No exact lambda_2 or certified eigenpair claim is made. Candidate inventory and explicit marker policy are independent of the cut. Disconnected graphs receive exact zero global connectivity but still retain every candidate in the report.

## Migration

Audits no longer run package managers or delete locks. Resolution snapshots do not claim installed instance placement. Cross-format comparisons return incomplete rather than compare incompatible keys. `--network`, the legacy daemon and unqualified CLI ecosystems return incomplete/usage errors. pnpm v9 parsing preserves versions/peer and patch context, namespaces environment/project documents, retains importer/workspace links and validates root specifiers. Capabilities remain explicitly unknown. Yarn Classic v1 preserves exact grouped descriptors and source/integrity, with supplied-root attribution; workspace manifests and peer installation are not inferred. Unsupported Berry versions and Classic record structures are rejected. Both emit useful normalized graphs and diffs with overall incomplete/exit2 while transitive scripts are unknown. Cargo metadata parsing recognizes build scripts and proc macros but is an incomplete preview, without Cargo subprocesses. The retired semver/network API cannot guess resolution. Legacy broad whitelists must be replaced with explicit coordinates. Existing threshold/mode values are validated but do not gate topology. Native result prefix is preserved; see the header for appended diagnostics and ownership.
