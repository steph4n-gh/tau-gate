# Owned-repository self-pilots

The two pilots started on 2026-10-20. They test Tau-Gate as an npm pull-request check in repositories owned by the same operator. Neither pilot provides external maintainer feedback or four weeks of use. Public package lifecycle scripts were not run during setup or the controlled updates.

## Method and scope

Each repository uses a `pull_request_target` workflow from its trusted base commit. The workflow reads both Git snapshots as objects, downloads the pinned [v4.2.1 release](https://github.com/steph4n-gh/tau-gate/releases/tag/v4.2.1), checks the archive SHA256, and runs the vendored review helper. The helper reads approvals from the base commit. It returns allowed, blocked, or incomplete; a failed job must prevent ordinary merge once `tau-gate` is required. The [consumer guide](../pr-review.md) gives the installation and approval procedure.

The pilots exercise a genuine lockfile update, a helper upgrade, and deliberately failing pull requests. A failing control stays open long enough to inspect its report and merge restriction, then closes without merging. The [pilot log](pilot-log.tsv) records exact heads, report outcomes, and policy transitions. Review minutes were not timed for the initial work.

The four-week observation window runs from 2026-10-20 through 2026-11-17. Each later update review should record the PR head, gate result, evidence gaps, reviewer minutes, and administrative policy changes. A week with no dependency update should say so instead of being counted as a successful review. The window can close only after actual use across the interval; elapsed time alone is insufficient.

## Earthquake Lab Publication

The [postcss update](https://github.com/steph4n-gh/earthquake-lab-publication/pull/2) changed the npm lock from 8.5.30 to 8.5.31. The v4.2.1 live gate allowed it with 45 qualified evidence instances. An independent replay checked the package archives and SRI values. The pull request merged, and its [main build](https://github.com/steph4n-gh/earthquake-lab-publication/actions/runs/39516726726) passed.

The [trusted helper upgrade](https://github.com/steph4n-gh/earthquake-lab-publication/pull/3) merged after exact-head CI and an [independent verdict](https://github.com/steph4n-gh/earthquake-lab-publication/pull/3#issuecomment-6304507137). The installed helpers match the v4.2.1 source bytes. The live upgrade check used the prior trusted base helper; an independent replay showed that the new helper blocks a head-side helper edit and allows the unchanged head.

The [merged-main build](https://github.com/steph4n-gh/earthquake-lab-publication/actions/runs/39518344661) passed at merge commit `5f6fb05d60b4000534381d20ac983f9a1bdbb15f`.

The [head-side approval control](https://github.com/steph4n-gh/earthquake-lab-publication/pull/4) changed only JSON formatting. Its [live report](https://github.com/steph4n-gh/earthquake-lab-publication/actions/runs/39518372790) returned blocked, exit 1, and named `tau-gate.approvals.json` as a protected head change. The [missing-lock control](https://github.com/steph4n-gh/earthquake-lab-publication/pull/5) returned incomplete, exit 2, and named `package-lock.json` as the missing Git path in its [live report](https://github.com/steph4n-gh/earthquake-lab-publication/actions/runs/39518391437). Both used the v4.2.1 checker and the new trusted helper from main. The `tau-gate` check is now required with up-to-date status checks on `main`; GitHub reported `mergeStateStatus: BLOCKED` for both controls. Both PRs closed without merging.

The [approval bootstrap](https://github.com/steph4n-gh/rea/pull/3) added two exact lifecycle fingerprints and a tracked-tree digest to the trusted base. The v4.2.1 gate blocked that bootstrap against the old empty approval file, as designed. An [independent verdict](https://github.com/steph4n-gh/rea/pull/3#issuecomment-6304371517) and green non-gate checks preceded its administrative merge.

The [helper upgrade](https://github.com/steph4n-gh/rea/pull/4) merged after 20 exact-head checks and an [independent verdict](https://github.com/steph4n-gh/rea/pull/4#issuecomment-6304572233). Its merge tree matches the reviewed PR tree. The live upgrade check used the old base helper, while an independent replay showed that the new helper blocks protected helper and policy edits.

The [merged-main CI run](https://github.com/steph4n-gh/rea/actions/runs/39518859586) passed at merge commit `78a04679ed2b4dea4cedc83524c14dbb62503dfe`. A fresh offline head-to-head review of that commit returned allowed with the current source-tree approval.

A genuine `ignore` 7.0.6 to 7.0.13 update is open as [PR #7](https://github.com/steph4n-gh/rea/pull/7). The npm tarball and lockfile SRI match. The first advisory gate run blocked it on the root `prepare` fingerprint and tracked-tree digest. [PR #6](https://github.com/steph4n-gh/rea/pull/6) staged both old and proposed values. Its live gate blocked only the two protected policy files, so a trusted administrator merged it after 19 green product checks and an [independent verdict](https://github.com/steph4n-gh/rea/pull/6#issuecomment-6304801414). The merged policy tree matches the reviewed PR tree. A fresh offline head-to-head review of merged main returned allowed. An independent prospective replay against the staged policy also allowed the exact two-file update with 552 SRI-indexed archives.

The [live PR #7 gate](https://github.com/steph4n-gh/rea/actions/runs/39520796768) returned allowed, exit 0, with no input errors. It used the published v4.2.1 binary, qualified 560 artifact instances per snapshot, found one package change and two execution-evidence changes, and matched the staged head digest. All 28 exact-head checks passed. The [independent verdict](https://github.com/steph4n-gh/rea/pull/7#issuecomment-6304969362) checked the npm archive, SRI, source digest, and live artifact. PR #7 merged at `33b179b5007056bf680432e1683da890ae542e22`; its merge tree matches the reviewed head tree and its [merged-main CI](https://github.com/steph4n-gh/rea/actions/runs/39521885701) passed.

The [policy-only cleanup](https://github.com/steph4n-gh/rea/pull/8) removed only the two superseded approval values. Its [live gate](https://github.com/steph4n-gh/rea/actions/runs/39521932931) blocked exit 1 solely on those protected paths; all 19 product checks passed. An [independent verdict](https://github.com/steph4n-gh/rea/pull/8#issuecomment-6305107894) checked the exact diff, live artifact, and a prospective head-to-head replay that allowed the cleaned policy. The administrator merge at `5e97e042a66d88064cbec623c4e8b0f3ecb184e6` has the reviewed head tree. A fresh replay of that exact merged commit as both revisions returned allowed, exit 0, with the new source digest and 560 qualified artifact instances. This self-comparison verifies the current policy baseline, not the safety of runtime scripts. Its [merged-main CI](https://github.com/steph4n-gh/rea/actions/runs/39522987878) passed all 17 jobs.

The REA `CI` workflow was found in the `disabled_manually` state after the staged-policy merge, so that merge has no main CI run. It was restored before PR #7 opened, and the PR #7 and final cleanup main CI runs passed. After the final green run, the workflow again changed to `disabled_manually`. No in-repository disable command was found, and the operator did not know the cause. It was restored to active, but the recurring toggle needs investigation before relying on product CI for future updates. The separate required `tau-gate` workflow remained active. The staged-policy merge has exact-tree, PR CI, and offline gate evidence, but no green merged-main CI claim.

The [script-only control](https://github.com/steph4n-gh/rea/pull/5) changed `scripts/prepare.mjs` without changing `package.json`. The [live gate report](https://github.com/steph4n-gh/rea/actions/runs/39518895787) returned blocked, exit 1, with no input errors. It reported zero package and lifecycle-evidence changes and an unapproved tracked-tree digest. `tau-gate` is now required with up-to-date status checks on `main`; GitHub reported `mergeStateStatus: BLOCKED` for the control. The PR closed without merging.

REA's separate [Release workflow](https://github.com/steph4n-gh/rea/actions/runs/39522987743) fails when `release-please-action` tries to create a pull request because repository Actions are not permitted to create or approve PRs. The same failure occurred on earlier main merges. This is distinct from Tau-Gate and the repository's CI workflow; no release was published from these pilot merges.

## Limits and open evidence

The REA source-tree approval binds tracked Git entries, so even an unrelated tracked change needs a reviewed digest while a source-project lifecycle candidate exists. The staged transition costs at least a policy review, the update review, and a policy cleanup. Neither repository has yet shown sustained review effort. One operator owns both repositories, so these pilots cannot establish independent human approval. A source-tree digest does not cover untracked files, install-generated files, network responses, or the runtime environment.

Pilot misses are defined against specific events: an allowed result after an unapproved script or tracked-source change, a substituted archive, or missing required evidence. These controls cannot support a general malware-detection claim. The four-week self-pilot interval and external maintainer feedback remain open evidence gates.
