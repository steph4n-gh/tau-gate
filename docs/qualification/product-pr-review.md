# npm v3 PR review product milestone

The local technical workflow now completes one real dependency update without a fingerprint-policy PR. A report made from trusted Git objects shows the locked change, typed route, exact qualified lifecycle command text, artifact and manifest hashes, unknown evidence, and the next action. A trusted maintainer records one exact subject in an external store, then the same head changes from blocked to allowed. No public package lifecycle script was executed.

This is **not a release qualification**. The [fourth historical cohort](npm3-full-sprint.md) stays frozen at 10/30 complete. The later [candidate decision](product-release-decision-20261110.md) records a five-round repository-disjoint replay at 17/30 complete, below its frozen coverage floors. Hosted positive comment approval, five outside-maintainer uses, a blinded review comparison, and a signed versioned release remain open. The [local-work receipt](evidence/product-pr-review-20261110.json) binds the earlier blocked-to-allowed replay, controls, and fuzz run to source and binary hashes. Large inputs and raw logs remain under ignored `ecosystem_audit/product-pr-review-20261110`.

## What changed

- The trusted [PR helper](../../tools/pr_review.py) adds a reviewer view to `report.json` and `summary.md`. It prioritizes changed lifecycle bodies and checks displayed command text against the qualified manifest hash. It reconstructs typed dependency routes from the core's edges. It shows all unknown package sides in JSON and groups them in Markdown. A 30-change display limit is explicit; a truncated view cannot generate a one-action approval request.
- `--approval-store` reads administrator-controlled records outside the PR repository. A complete blocked report gives `approval_request.subject_sha256`. The maintainer runs the same helper with `--approve-subject` and a new output directory. It recaptures Git objects and evidence, requires the same subject, and writes one owner-only record. A later ordinary review reruns the Rust policy checker with the exact additional fingerprints. Changed heads, evidence, source tree, base policy, or tool bytes invalidate the subject. Protected head edits and incomplete evidence cannot request approval. The original base-policy mode still works.
- The tar inspector returns borrowed static text for its ordinary rejection reasons; the production boundary still converts errors to owned text. This removes repeated small allocations from the continuous tar fuzz path without changing accepted archive facts or rejection messages.
