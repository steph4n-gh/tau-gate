# Fresh repository validation protocol

This protocol was frozen before collecting fresh project inputs. Design uses the original152 lockfiles only. The fresh cohort is a single prospective evaluation: no tuning or replacing failed cases after outcomes are exposed.

Candidate: unchanged four-projection spectral search plus an exact O(n+m) iterative bridge scan. The primary cut minimizes ratio cut, with conductance as tie-breaker; equal candidates preserve spectral provenance. A conductance alternative remains separate. Selecting a bridge cut is explicitly a structural/hybrid result, not a spectral gain. The original spectral partition is retained in `spectral_alternative` when a bridge wins. The Rayleigh solver, residual tolerance and work caps are unchanged. Bridge cuts have no spectral projection/threshold; legacy C tau is zero, the C layout is unchanged. Public Rust projection fields become the typed `CutOrigin`, a source compatibility change for direct Rust consumers.

Choose the next200 unique canonical GitHub repository identities in the same pinned critical npm ranking, excluding all original200 repositories and canonical aliases. Pin commits and acquired source hashes; preserve failed/archived/no-lock/unsupported/incomplete cases. Use the prior discovery and explicit source-context rules without package installation or dependency execution.

One lock per repository is preselected by filename priority: package-lock, npm-shrinkwrap, pnpm-lock, Yarn, Bun text, Bun binary; then path order. Primary cases must be topology-complete, connected, >1node, within20000nodes/200000edges, with converged first-direction diagnostics and an independently matching numerical reference. Exclude exact labeled undirected multigraph topologies already in the old152 or a preceding eligible fresh primary; keep and report them. This does not exclude all isomorphic graphs or shared transitive packages. Report all eligible locks separately.

Run frozen baseline, candidate and unchanged deterministic BFS-subtree/bridge/component plus degree-cut reference candidates. Report primary ratio cut and conductance separately, plus actual cut origins and separately selected conductance profile. Measure pure-spectral strict wins and >1percent ratio gains over basic, not just the hybrid's predictable no-regression property. Five interleaved repetitions check determinism; no speedup claim is intended.

Retain every input/acquisition/numeric/reference failure with per-case receipts and aggregate status. Any code or harness issue discovered after outcomes must be disclosed; this cohort cannot be reused as a fresh test after tuning. The frozen source/hash protocol is in local `ecosystem_audit/math-fresh-validation-20261109/frozen.json`. Two pre-acquisition preflight amendments preserve earlier hashes: failure retention, then baseline identity and explicit profile accounting. No fresh snapshots or outcomes were acquired before those amendments.

This is a later slice of the same critical npm ranking, not a random sample or cross-ecosystem validation. It tests structural generalization, with no fresh harmfulness, artifact-event or human-review labels. The [completed study](math-fresh-validation.md) reports all outcomes and independent closure review. After acquisition began but before outcome evaluation, a third harness amendment separated parser-order CLI metadata from canonical C-ABI scoring. Candidate code and eligibility remained frozen; the full hash chain is retained.
